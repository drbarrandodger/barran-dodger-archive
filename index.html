Preservation principle

Original evidence remains preserved. Presentation structure, navigation and descriptive copy may change over time, but underlying records, filenames, source paths and documentary artefacts must not be overwritten, renamed or silently normalised.
  • Primary-source files stay in place and are referenced by stable repository paths.
  • Phase 1 introduces only architecture, inventory, navigation and status-language foundations.
  • Potentially sensitive material is not newly surfaced by default in this shell.

Initial navigation model

The public shell is intentionally limited to high-trust orientation pages until later archive phases are implemented.

These labels distinguish provenance and certainty without relying on colour alone. They are architectural definitions only; applying them across the corpus is reserved for later phases.

Basic search framework / shell

Phase 1 intentionally limits browser-side search to navigation, preserved collections and architectural surfaces. The full documentary corpus is not loaded into the browser by default here.

Inventory and preservation references

A machine-readable pre-restructure repository snapshot has been created and kept outside the published shell so it can preserve original internal paths without automatically surfacing additional sensitive material.

Privacy boundary: filenames and classifications already present in the repository may identify sensitive or official material. Phase 1 therefore keeps the inventory in repository documentation rather than publishing it as a new browsable public index.
